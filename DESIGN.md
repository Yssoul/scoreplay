# Design Decisions

This document records the architectural and technical choices made while
building the ScorePlay media-indexing API. It is intentionally a living
log: each entry states the **decision**, the **why**, and (where it
matters) the **trade-offs** and **what would change in production**.

The aim is to give a reviewer the full reasoning without forcing them
to read every commit.

---

## 1. Language, runtime, dependencies

### 1.1 Go 1.25, standard library `net/http` router

- One less dependency to audit, upgrade, and explain. The router stays
  swappable: handlers are plain `http.Handler` values.

### 1.2 `pgx/v5` + `sqlc` + `tern`

- **pgx** for the driver: it is the recommended Postgres driver for
  Go, exposes Postgres-specific features (CITEXT, UUID, COPY) and is
  used directly by `sqlc`.
- **sqlc** for query code generation: SQL stays first-class and
  reviewable; we get type-safe Go on top, with zero runtime ORM cost.
- **tern** for migrations: small, single-binary, written by the same
  author as `pgx`, integrates cleanly with the test pool (see §6).

### 1.3 UUIDv7 for every primary key

- Time-sortable: cheaper indexes than v4, friendlier for log-based
  debugging and for keyset pagination later.
- Generated by the application (not the database).

## 2. HTTP layer

### 2.1 RFC 7807 `application/problem+json` for every error response

- One uniform shape (`type`, `title`, `status`, `detail`) for clients.
- Sentinel errors in `internal/httpx` (`ErrBadRequest`, `ErrConflict`,
  `ErrInternal`, …) map to HTTP statuses; handlers compose them via
  `fmt.Errorf("%w: detail: %w", httpx.ErrXxx, cause)`. The transport
  layer is the single place that decides how an error is rendered.
- 5xx responses never embed the underlying `err.Error()` (asserted by
  `assertNoErrorLeak` in the handler tests). Internal errors are
  logged, not exposed.

### 2.2 Listing endpoints always return `[]`, never `null`

- A nil slice in Go marshals to `null`, which forces every client to
  add a null-guard.
- Both the repository (`make([]Tag, 0, len(rows))`) and the handler
  (`if list == nil { list = []Tag{} }`) enforce this. The contract is
  pinned by `TestListTags_EmptyReturnsEmptyArray`.

### 2.3 Request body size is capped per endpoint

- `http.MaxBytesReader` on every endpoint that parses a body, with a
  per-resource limit (1 MiB for JSON, larger for media uploads when
  added). This is a baseline DoS defense.

## 3. Storage layer

### 3.1 Domain `tags.Tag` is decoupled from sqlc-generated `db.Tag`

- `internal/tags/repository.go` maps `db.Tag → tags.Tag` row by row.
  The domain type is the bounded-context's source of truth; the
  generated type is an infra detail.
- Cost: ~5 lines per query.
- Benefit: the database schema can evolve (extra columns, renames)
  without leaking into the domain or the HTTP contract. This is a
  classic anti-corruption layer.

### 3.2 `name CITEXT` + `UNIQUE (name)` on `tags`

- Prevents `"Messi"` and `"messi"` from coexisting, which is the
  business rule.
- The repository translates Postgres `SQLSTATE 23505` into the
  domain-level sentinel `tags.ErrNameConflict`, so handlers do not
  depend on `pgconn.PgError`.

### 3.3 Blob storage is abstracted behind `blobstore.Store`

- Three methods only: `Put`, `Open`, `Delete`. `Open` returns
  `io.ReadSeekCloser` so `http.ServeContent` can honour HTTP `Range`
  requests for free (essential for video).
- One implementation today: `fsstore`, persistent, used in development
  and for the take-home deliverable. Handler tests will define their
  own focused fake in `*_test.go` (counting `Put` calls, returning
  errors on demand to test rollback compensation, …): a generic
  in-memory `Store` would not give those assertions for free, so it
  would be code without a consumer.
- Compile-time assertions (`var _ blobstore.Store = (*fsstore.Store)(nil)`)
  guarantee that any signature drift surfaces at build time.

#### 3.3.1 Why filesystem first

A production deployment would point this interface at S3 (or any
S3-compatible service such as MinIO, R2, B2). For the scope of this
take-home, the filesystem implementation:

- requires zero external infrastructure to evaluate;
- keeps the interface narrow: only the methods we actually need today
  exist, which makes the eventual S3 implementation easier to validate
  against the same contract;
- can be swapped for an S3 backend in roughly one new file
  (`internal/blobstore/s3store/`), one factory branch in `cmd/api`
  and one `docker-compose` service. No handler change.

The interface was deliberately kept narrow so this swap is mechanical.

#### 3.3.2 Why no `contentType` on `Put`

The MIME type is **metadata about the resource**, not about the
storage backend. It will be persisted in `media.content_type` (the
single source of truth) and served via `http.ServeContent`, which
reads it from the database row. Re-passing it to the blob store today
would only matter for object-storage backends that propagate it as
S3/GCS object metadata. When that backend is added, the parameter is
trivial to introduce; until then it is dead weight.

#### 3.3.3 Atomicity contract

`fsstore.Put` writes to `<root>/tmp/<random>` then `os.Rename`s into
`<root>/blobs/<key>`. On the same filesystem, `rename(2)` is atomic,
so a concurrent `Open` either sees the fully written file or
`ErrNotFound`. `f.Sync()` runs before `Close` so a kernel crash
cannot leave a zero-byte file masquerading as a successful upload.
The contract is locked by `TestPut_Concurrent_NoCorruption`, which
runs under `-race`.

#### 3.3.4 Key validation as defense in depth

Callers always pass UUIDv7 strings, but `fsstore` still validates
keys against `^[a-zA-Z0-9_-]{1,128}$` before touching the
filesystem. This rules out path traversal (`../`), separators, and
absurd lengths even if a future caller passes user input.

## 4. Project layout

```
cmd/api/                     # process entrypoint, wiring only
internal/
  config/                    # env-driven configuration
  httpx/                     # transport-level helpers (problem+json, json, log)
  postgres/                  # pgx pool factory
  blobstore/                 # binary-object abstraction
    fsstore/                 # filesystem implementation
  tags/                      # tag bounded context
    db/                      # sqlc-generated code (infra)
    integration/             # //go:build integration tests
db/
  migrations/                # tern migrations
  queries/                   # sqlc input
```

Everything outside `cmd/api` is `internal/` so external consumers
cannot import implementation details. Each bounded context (`tags`,
soon `media`) keeps its handler, repository, and integration tests in
its own folder, so a new domain looks identical to an existing one.

## 5. Configuration

- `internal/config` reads from environment variables, fails fast at
  startup if required values are missing.
- A `.env` file is loaded by the Makefile only; the Go binary itself
  does not parse `.env`, which keeps production deployments free of
  dotfile magic.

## 6. Testing strategy

Three layers, each with a clear cost/coverage trade-off:

### 6.1 Unit tests — fast, no Docker

- `go test ./...` runs in seconds.
- Handler tests use `httptest.NewRecorder` + a focused fake defined
  inside the same `_test.go` (e.g. `fakeTagRepository`). Storage
  tests use `t.TempDir()` so each run sees an isolated filesystem.
- Run on every `go test`, on every CI build.

### 6.2 Integration tests — `//go:build integration`, real Postgres

- `go test -tags integration ./...` boots a fresh Postgres 16
  container per test via testcontainers-go, applies every migration
  via `tern`'s Go API, and exercises the **public API** of each
  package (no white-box reach-in).
- One container per top-level test guarantees isolation. The
  ~1.5 s cold-start is a fair price for deterministic data state.

### 6.3 Race detector everywhere it matters

- The blob store tests run under `-race` because their atomicity
  guarantee is concurrency-sensitive. Adding `-race` to the standard
  CI pipeline is a follow-up.

### 6.4 Test conventions

- Sentinel-error checks use `errors.Is`, never string matching.
- Reusable assertion helpers live in `*_test.go` next to the suite
  that needs them (`assertProblemJSON`, `assertNoErrorLeak`), which
  keeps the contract explicit and shared.

## 7. What would change with more time

Listed in the order they would deliver the most value.

1. **S3-compatible backend (MinIO in dev, S3 in prod).** Add
   `internal/blobstore/s3store/`, a `minio` service in
   `docker-compose.yml`, and a config-driven factory. The interface
   is already minimal enough to make this drop-in. Presigned `GET`
   URLs would let a CDN serve media directly.
2. **Pagination on listing endpoints.** Keyset cursor over
   `(name, id)` for `GET /tags` and `(created_at DESC, id)` for
   future `GET /media`. Avoids future breaking changes to the API
   contract.
3. **Search media by tag.** The schema (`media_tags(tag_id)` with an
   index) is designed for it; only a query and a route would be
   missing.
4. **Authentication and rate-limiting.** Out of scope for the take-home,
   but the `httpx` layer is the natural place to add middleware.
5. **OpenAPI spec + generated types.** The handlers are simple enough
   that an OpenAPI-first workflow (`oapi-codegen`) would pay off
   quickly.
6. **Observability (OpenTelemetry).** Trace HTTP → repository →
   pgx; pre-instrumented packages exist for each layer.
7. **Garbage collection of orphan blobs.** The `POST /media`
   transaction will best-effort delete the blob on rollback, but a
   periodic reconciliation job would catch leaks from crashes.
